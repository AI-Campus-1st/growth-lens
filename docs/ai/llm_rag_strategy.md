# LLM · RAG 전략

- 작성일: 2026-11-25 · 담당: 김한승 · 상태: **[제안]**

## 1. 핵심 판단: RAG가 정말 필요한가?
이 프로젝트의 핵심 정보는 대부분 **구조화된 수치 결과**입니다. 이를 프롬프트에 직접 넣는 방식(비-RAG)으로도 브리핑이 가능하므로, RAG는 **측정 가능한 개선이 있을 때만** 도입합니다.

RAG가 가치를 낼 가능성이 있는 영역 [가정]:
- 지표 정의·방법론·한계를 묻는 질문 ("Opportunity Score는 어떻게 계산돼?")
- 승인된 과거 월간 리포트 검색 ("지난달 대비 무엇이 달라졌어?")
- 데이터 사전 기반 용어 설명

RAG가 부적합한 영역:
- 정확한 수치 조회 → 구조화 조회
- 계산·집계 → SQL/Python

## 2. 단계적 도입
| 단계 | 내용 | 진입 조건 |
|---|---|---|
| 0 | 템플릿 리포트 (LLM 없음) — 비교 기준 | — |
| 1 | 구조화 컨텍스트 + LLM 브리핑 (비-RAG) | 모듈 표준 출력 확보 |
| 2 | RAG 추가 (문서 검색 + 구조화 조회) | 1단계 평가셋 구축 완료 |
| 판정 | 2단계가 1단계 대비 평가 지표 개선 시에만 채택 | `ai_evaluation_plan.md` |

## 3. 지식 베이스 (RAG 대상) 후보
| 문서 | 위치 | 승인 주체 |
|---|---|---|
| 지표 정의·데이터 사전 | `docs/data/` | 각 모듈 담당 |
| 모듈 방법론·한계 보고서 | `docs/reports/` | 각 모듈 담당 |
| 승인된 월간 리포트 | `outputs/reports/` (승인본만) | 김한승 |
| 검증된 시장 자료 | `data/knowledge/` | 출처·라이선스 확인 후 |

- 원칙: **승인된 문서만** 인덱싱, 문서마다 출처·작성일·버전 메타데이터
- 라이선스상 재배포 불가 자료는 인덱스에 넣지 않음

## 4. 프롬프트 원칙
- 시스템 프롬프트에 "제공된 컨텍스트 밖의 수치 생성 금지", "인용 필수", "5개 라벨 구분" 명시
- 컨텍스트에 manifest의 `result_type`, 시장, 기간, 한계를 함께 주입
- 권고는 근거(결과 ID 또는 문서 ID)와 1:1 연결
- 프롬프트 파일은 `src/ai/prompts/` 에서 버전 관리

## 5. 기술 선택 기준 (미정, W2 결정)
| 항목 | 기준 |
|---|---|
| LLM | 한국어 품질, 비용, API 안정성, 팀 예산 |
| 임베딩 | 한국어 검색 성능, 비용 |
